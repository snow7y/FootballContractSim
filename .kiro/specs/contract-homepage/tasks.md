# Implementation Plan

- [x] 1. 契約とユーザーのデータ基盤を追加する
- [x] 1.1 契約をユーザーに関連付けて保存できるデータ構造を用意する
  - 契約データに「誰の契約か」を表す関連付けを追加する
  - 契約が選手とクラブに必須で紐づく前提をデータ整合性で担保する
  - 契約の参照でユーザー単位に絞り込みできるように検索しやすい状態にする
  - _Requirements: 4.2,6.3,6.4_

- [x] 1.2 ユーザーの最小データモデルを追加する
  - 契約操作に利用するユーザーを識別できる永続データを追加する
  - ユーザーが存在しない場合でも後続の「作成」手段で成立する前提を確認する
  - _Requirements: 6.1,6.2_

- [x] 2. ユーザーコンテキストを提供する
- [x] 2.1 現在ユーザーを識別・保持できる仕組みを実装する
  - 現在ユーザーをサーバー側で参照できる状態を作る
  - 現在ユーザーが未設定の場合に「未選択」として扱えるようにする
  - _Requirements: 6.1,6.2_

- [x] 2.2 ユーザーの選択と新規作成を行える操作を提供する
  - 既存ユーザー一覧から現在ユーザーを切り替えられるようにする
  - 新規ユーザーを作成できるようにする
  - 作成/選択後は現在ユーザーが確定した状態に遷移させる
  - _Requirements: 6.2_

- [x] 3. 契約作成とスコープ制御を実装する
- [x] 3.1 契約入力の検証とエラー分類を実装する
  - 契約期間の整合（開始日と終了日）と必須入力を検証する
  - 報酬など数値入力の範囲と形式を検証する
  - 検証エラーがある場合に契約確定を成立させない
  - _Requirements: 3.2,3.3_

- [x] 3.2 契約確定により契約を作成し、結果を返す
  - 選手とクラブの存在を確認した上で契約を作成する
  - 作成される契約を現在ユーザーに関連付けて保存する
  - 作成成功時に参照可能な情報を返す
  - _Requirements: 4.2,4.4,6.3_

- [x] 3.3 契約参照を現在ユーザーの範囲に制限する
  - 現在ユーザーに関連付かない契約が参照対象になった場合は拒否する
  - 現在ユーザーの契約のみを表示・参照対象にできるようにする
  - _Requirements: 6.4,6.5_

- [x] 4. ホーム画面で契約フローを提供する
- [x] 4.1 ホーム画面に契約開始導線と状態表示を追加する
  - 契約開始の主要な導線と簡潔なフロー概要を表示する
  - 契約対象の有無など契約可能状態を明示する
  - 契約対象がない場合の空状態と次の行動を提示する
  - _Requirements: 1.1,1.2,1.3,5.3,5.4_

- [x] 4.2 契約対象の選択UIを実装する
  - 選手とクラブの選択肢を提示し、選択結果の識別情報を表示する
  - 必須選択が未完了の間は契約確定を許可しない
  - 無効な選択や不整合がある場合に修正可能なエラーを表示する
  - _Requirements: 2.1,2.2,2.3,2.4_

- [x] 4.3 契約条件の入力UIを実装する
  - 契約期間と報酬などの必須条件を入力できる
  - 入力値の不正を分かりやすく表示し、確定を許可しない
  - 入力済み条件の要約を表示する
  - _Requirements: 3.1,3.2,3.3,3.4,5.2_

- [x] 4.4 契約内容の確認と確定の体験を実装する
  - 最終確認表示を提供し、ユーザーが確定前に内容を見直せる
  - 契約確定処理中は処理中であることを示すフィードバックを表示する
  - 失敗時は理由と再試行手段を表示する
  - 成功時は作成された契約の参照情報を提示する
  - _Requirements: 1.4,4.1,4.2,4.3,4.4,5.1_

- [x] 5. テストで契約フローとユーザー分離を検証する
- [x] 5.1 (P) 契約作成が永続化されることをデータ層で検証する
  - 契約が作成でき、必要な関連付けが保存されることを確認する
  - 参照時にユーザー単位で絞り込みできることを確認する
  - _Requirements: 4.2,6.3,6.4_

- [x] 5.2 (P) ユーザー分離が破られないことを検証する
  - 別ユーザーの契約が参照対象にならないことを確認する
  - 不正参照が要求された場合に拒否されることを確認する
  - _Requirements: 6.4,6.5_

- [x] 5.3 (P) UI の主要状態が成立することを構造テストで検証する
  - 主要な導線、処理中表示、エラー表示が実装されていることを確認する
  - _Requirements: 1.1,4.3,5.1,5.2_

- [x] 6. 統合とリグレッションを行う
- [x] 6.1 既存の選手/チーム管理導線を維持する
  - ホーム画面から既存管理機能へ到達できる状態を維持する
  - _Requirements: 5.3_

- [x] 6.2 エラーと空状態の最終調整を行う
  - 契約対象なし、未選択、検証失敗、作成失敗の各状態で表示が破綻しないことを確認する
  - _Requirements: 1.3,2.4,3.2,4.3,6.2_
