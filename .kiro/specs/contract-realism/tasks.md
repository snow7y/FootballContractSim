# Implementation Plan

## Task Breakdown

### 1. シミュレーション設定管理の実装
- [x] 1.1 (P) シミュレーション設定サービスを作成
  - 推奨年俸比率（5-15%）、契約期間の年齢別パラメータ、妥当性検証しきい値を定義
  - 交渉成功率マッピング（期待年俸比率と成功率の関係）を設定
  - 市場価値更新の補正係数（若手スター・ベテラン）を定義
  - すべての設定値をimmutableオブジェクトとして公開
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 2.1, 2.2, 2.3, 2.4, 3.1, 3.2, 3.3, 3.4, 5.1, 5.2, 5.3_

### 2. 契約条件推奨サービスの実装
- [x] 2.1 (P) 推奨条件算出機能を実装
  - 選手の市場価値から推奨年俸範囲を算出（設定の比率を適用）
  - 選手の年齢・ポテンシャルから推奨契約期間を算出
  - 算出根拠を含む推奨条件オブジェクトを返却
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5_

- [x] 2.2 (P) 妥当性検証機能を実装
  - 年俸が市場価値の20%超過時に過剰評価警告を生成
  - 年俸が市場価値の3%未満時に低評価警告を生成
  - 能力値と年俸のミスマッチを検出（能力値70未満で週給20,000超過）
  - 18歳未満で契約期間3年超過時に長期契約リスク警告を生成
  - 警告タイプ・メッセージ・重要度を含む検証結果を返却
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5_

- [x] 2.3 (P) 交渉成功率算出機能を実装
  - 選手の期待年俸（市場価値の8%）を計算
  - 提示年俸と期待年俸の差分から成功率を算出
  - 期待年俸比率に応じた成功率マッピング（90%未満→30%以下、90-110%→70-80%、110%以上→95%以上）
  - 成功率・期待年俸・年俸差分を含む結果オブジェクトを返却
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5_

### 3. 選手発言生成サービスの実装
- [x] 3.1 (P) ルールベース発言生成機能を実装
  - 交渉結果（成功/失敗）と年俸差分から発言カテゴリを判定
  - 選手属性（年齢・能力値・ポテンシャル）から発言トーンを調整
  - 成功時の発言テンプレート（若手・ベテラン・スター別に3-5パターン）
  - 失敗時の発言テンプレート（年俸不足を間接的に示唆）
  - 試行回数3回以上で厳しい態度の発言に変化
  - _Requirements: 3.6, 3.7, 4.1, 4.2, 4.5, 7.3, 7.4, 7.5_

- [x] 3.2 (P) AI統合インターフェースを定義
  - AI発言生成プロバイダーのインターフェースを定義
  - 交渉コンテキスト（選手属性・年俸差分・試行回数）の構造化
  - Phase 2でのLLM統合を見据えたメソッドシグネチャ
  - フォールバック機構（AI失敗時はルールベースに切り替え）のスタブ実装
  - _Requirements: 7.1, 7.2, 7.6, 7.7_

### 4. 契約作成アクションの拡張
- [x] 4.1 交渉判定ロジックを統合
  - 推奨サービスから交渉成功率を取得
  - ランダム判定でサーバ側での成功/失敗を決定
  - 成功時：既存のContract作成処理を実行
  - 失敗時：Contract作成をスキップし、早期リターン
  - _Requirements: 3.1, 3.5_

- [x] 4.2 選手発言の記録を統合
  - 交渉成功時：発言生成サービスから成功発言を取得
  - 交渉失敗時：発言生成サービスから失敗発言を取得
  - ActionLogに選手発言をmessageフィールドで記録
  - 試行回数追跡（ActionLog解析で同一選手への失敗回数を計算）
  - _Requirements: 3.6, 3.7, 4.1, 4.3, 4.4_

- [x] 4.3 市場価値と年俸の動的更新を実装
  - 契約締結成功時にPlayerレコードの市場価値を更新
  - 年俸×12を基礎市場価値として計算
  - 年齢・能力値による補正係数を適用（若手スター×1.2、ベテラン×0.7）
  - Player.wageフィールドを契約時の年俸で更新
  - トランザクション内でContract作成とPlayer更新を実行
  - ActionLogに市場価値更新の前後値を記録
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 5.5_

### 5. 契約フローUIの拡張
- [x] 5.1 選手選択時の推奨条件表示を実装
  - 選手選択時に推奨サービスから推奨条件を取得
  - 推奨年俸範囲と推奨契約期間をインラインで表示
  - 算出根拠をツールチップまたはヒントテキストで表示
  - ステートに推奨条件を保存し、UI再レンダリング時に参照
  - _Requirements: 1.5, 6.1_

- [x] 5.2 リアルタイム妥当性検証UIを実装
  - 年俸・契約期間入力時にdebounce（500ms）で妥当性検証を実行
  - 警告があればamber色のアラートボックスで即座表示
  - 警告タイプ別のメッセージとアイコンを表示
  - 警告があっても契約作成を阻止しない（情報提供のみ）
  - _Requirements: 2.5, 6.2_

- [x] 5.3 交渉成功率予測表示を実装
  - 契約作成ボタンクリック前に成功率を取得
  - 成功率をパーセンテージで表示（例：「成功率: 75%」）
  - 確認セクション内で視覚的に強調表示
  - _Requirements: 6.3_

- [x] 5.4 ヘルプアイコンとツールチップを追加
  - 各入力フィールドに「？」ヘルプアイコンを配置
  - ツールチップで計算ロジック・推奨範囲・注意事項を説明
  - 推奨条件の算出根拠をツールチップで詳細表示
  - _Requirements: 6.6_

### 6. アクションフィードバックUIの拡張
- [x] 6.1 選手発言フィードバック表示を実装
  - 既存のActionFeedbackコンポーネントはmessage表示ロジックを再利用
  - 成功時はemerald色、失敗時はred色のバッジを表示
  - 発言内容に応じた視覚的インジケータ（アイコン・色）を調整
  - _Requirements: 6.4, 6.5_

### 7. アクション履歴UIの拡張
- [x] 7.1 発言履歴表示を実装
  - 既存のActionHistoryコンポーネントはmessage表示ロジックを再利用
  - 成功/失敗をアイコンで識別（✅成功、❌失敗）
  - 選手の発言が履歴一覧で読みやすく表示されることを確認
  - _Requirements: 4.2_

### 8. 単体テスト

  - _Requirements: 1.1, 1.2, 1.3, 1.4_

- [x] 8.3 (P) 妥当性検証のテストを作成
  - 過剰評価警告生成（市場価値の20%超過）
  - 低評価警告生成（市場価値の3%未満）

### 9. 統合テスト

## Implementation Notes

### タスク実行順序の推奨
1. **Phase 1（独立実装）**: Task 1.1, 2.1, 2.2, 2.3, 3.1, 3.2は並列実行可能
2. **Phase 2（統合）**: Task 4.1, 4.2, 4.3は2.3と3.1の完了後に実行
3. **Phase 3（UI）**: Task 5.x, 6.1, 7.1は4.xの完了後に実行可能（一部並列可）
4. **Phase 4（テスト）**: Task 8.xは各コンポーネント完了後に並列実行可能
5. **Phase 5（統合・E2E）**: Task 9.x, 10.xはすべての実装完了後に実行

### 重要な依存関係
- Task 4.x（契約アクション拡張）は Task 2.3（成功率算出）と Task 3.1（発言生成）に依存
- Task 5.x（UI拡張）は Task 2.x（推奨サービス）に依存
- Task 9.x（統合テスト）は対応する実装タスクの完了に依存
- Task 10.x（E2Eテスト）はすべての実装タスクの完了に依存

### オプションタスクの扱い
- Task 10.3はMVP後のテストカバレッジ向上として延期可能
- 実装優先度が高いのは Task 1.1～4.3、5.1～5.3、6.1、7.1

### シミュレーション設定の調整
- 実装後1週間でTask 1.1の設定値を監視し、必要に応じて微調整
- 交渉成功率が極端に偏る場合は設定のみ変更（ロジック変更不要）
