# Implementation Plan

- [x] 1. テスト実行入口の統一
- [x] 1.1 (P) ローカル/CI の実行モードを単一入口で提供し、未知モード時の案内を整える
  - 実行モードの選択肢を固定し、入口の利用方法が明確になるようにする
  - ローカルと CI の既定セットを同一入口で実行できるようにする
  - _Requirements: 1.1, 1.2, 1.3, 1.4_
- [x] 1.2 既存テストをレガシーハーネスで統合実行できるようにする
  - `.test.js` と `.test.ts` を一貫して実行できるようにする
  - 実行結果が失敗時に正しく停止・集計されるようにする
  - _Requirements: 1.1, 1.2_
- [x] 1.3 Vitest 実行の基本出力と機械可読出力を整える
  - 要約情報が標準出力で確認できるようにする
  - 機械可読出力で同一の情報が取得できるようにする
  - _Requirements: 3.1, 3.4_

- [x] 2. 対象選択と実行前検証
- [x] 2.1 (P) 対象選択の解決ルールを整備する
  - 領域指定とファイル指定の解決を行えるようにする
  - 対象不存在時に候補を提示できるようにする
  - 複数対象を単一実行に統合できるようにする
  - _Requirements: 2.1, 2.2, 2.3, 2.4_
- [x] 2.2 (P) 実行前検証を共通化する
  - ローカル/CI で共通の前提検証を実行できるようにする
  - 前提不足時の復旧手順を提示できるようにする
  - _Requirements: 4.1, 4.2, 4.3_

- [x] 3. 結果要約と可視化
- [x] 3.1 失敗詳細を含む結果要約を整形する
  - 成功/失敗/スキップ件数を要約として表示する
  - 失敗したテスト名と場所を提示する
  - _Requirements: 3.1, 3.2_
- [x] 3.2 実行中の進行状況表示を整える
  - 実行中に進行状況が確認できるようにする
  - _Requirements: 3.3_

- [x] 4. 統合と検証
- [x] 4.1 実行フローの統合動作を検証する
  - 入口 → 前提検証 → 対象解決 → 実行 → 要約の流れが一貫して動作することを確認する
  - ローカル/CI の既定セットが同一入口で動作することを確認する
  - _Requirements: 1.1, 1.2, 1.4, 2.1, 2.2, 2.4, 3.1, 3.2, 4.1_
- [x] 4.2 エラーハンドリングと案内を検証する
  - 未知モード時の案内が提示されることを確認する
  - 対象不存在時に候補が提示されることを確認する
  - 前提不足時に復旧手順が提示されることを確認する
  - _Requirements: 1.3, 2.3, 4.2_
- [x] 4.3 機械可読出力と進行状況の出力を検証する
  - 機械可読出力が要約と失敗詳細を含むことを確認する
  - 進行状況が実行中に表示されることを確認する
  - _Requirements: 3.3, 3.4_
